SYNOPSIS OF THE PROJECT

2.1 Problem Statement

Students learning algorithms benefit from resources that present explanations, examples, and opportunities to inspect algorithm behavior. Algorithm Hub brings these elements together with a browser-based Practice Lab and an authenticated 30-day curriculum with server-graded quizzes.

2.2 Objectives and Scope

2.2.1 Objectives

  • Systematic Algorithm Taxonomy: To catalog 93 classic and advanced algorithms across 12 distinct categories with detailed pseudocode, invariant explanations, and asymptotic bounds.
  • Interactive Visualizations: To provide interactive sorting, searching, tree, and graph visualizers.
  • Integrated Practice Lab: To provide a browser workspace supporting C, C++, Java, Python, and JavaScript through the Wandbox API.
  • Sequential 30-Day Guided Learning Track: To design a pedagogical curriculum requiring students to progress sequentially through 6 daily stages (Learn → Understand → Visualize → Practice → Quiz → Review).
  • Automated Assessment & Verification: To author 300 daily quiz questions and 4 milestone assessments (Days 7, 14, 21, 30) evaluated by a backend grading engine requiring ≥ 70% passing threshold.
  • Secure User Authentication & Persistence: To implement bcrypt password hashing and 7-day signed JWT tokens with server-side revocation on logout.

2.2.2 Scope

Algorithm Hub is a local web application for exploring algorithms and tracking guided learning. It uses an HTML, CSS, JavaScript, and Vite frontend, a Node.js/Express API, and SQLite persistence. Private-network access depends on local network configuration and was not tested in this review.

2.3 Process Description

  1. User Registration & Session Initiation: Learner registers with name, email, and password. The system stores salted bcrypt hashes and returns a signed JWT.
  2. Catalog & Knowledge Retrieval: Learners browse, search, and filter algorithms, then open the available explanations.
  3. Visualizations: Learners use the browser-based visualizers to inspect algorithm behavior.
  4. Practice Lab Code Execution: The browser sends code directly to the Wandbox API and displays the compilation response.
  5. Curriculum Progression & Activity Matching: In the 30-day dashboard, the learner completes the daily concept review and submits a computed output that must match a server-side test case.
  6. Graded Quiz & Milestone Assessment: The learner answers 10 multiple-choice questions. Achieving ≥ 70% marks the daily quiz passed. On milestone days (7, 14, 21, 30), a separate comprehensive assessment unlocks and must also be cleared to unlock subsequent days.

3.2 Theoretical Background

3.2.1 Algorithms and Complexity Analysis

An algorithm is a finite sequence of unambiguous instructions solving a computational problem. Efficiency is commonly described using asymptotic notation such as Big O, Big Ω, and Big Θ. The catalog stores time-complexity and auxiliary-space metadata; the automated complexity test validates catalog metadata rather than measuring runtime performance.

3.2.2 Technology Stack Justification

  • Frontend (HTML, CSS, JavaScript, Vite): Provides the multi-page browser interface and development/build tooling.
  • Backend (Node.js & Express): Provides asynchronous, non-blocking I/O ideal for concurrent API requests, authentication checking, and test grading.
  • Database (SQLite3): A file-based relational database used for accounts, learning progress, attempts, notifications, and curriculum content.
  • Security Layer (JWT & bcryptjs): Employs 10-round bcrypt salted password hashing and 7-day cryptographic JSON Web Tokens with a server-side revocation list.
  • External Compiler Integration: The Practice Lab calls Wandbox directly from the browser; it requires internet access and does not send source code through the project backend.

3.3 Survey of Literature and Research Analysis

CHAPTER IV

ANNEXURE: DATABASE STRUCTURE, LEARNING RULES, AND API

A.1 SQLite Schema & Physical Data Dictionary

The schema has exactly 11 tables:

  • users (id PK, name, email UNIQUE, password hash, createdAt)
  • learning_progress (userId/day composite PK, stage timestamps, dailyQuizPassed, latestScore)
  • quiz_attempts (id PK, userId FK, day, score, passed, submittedAt)
  • activity_attempts (id PK, userId FK, day, answer, accepted, submittedAt)
  • assessment_attempts (id PK, userId FK, assessmentId, score, passed, submittedAt)
  • notifications (id PK, notificationKey UNIQUE, userId FK, day, message, createdAt, readAt)
  • revoked_tokens (tokenHash PK, expiresAt)
  • algorithms (slug PK, categoryKey, categoryLabel, position, name, description, timeComplexity, auxiliarySpace)
  • lessons (day PK, title, level, minutes, objectivesJson, explanation, exampleJson, steps, activity, activityInput, activityHint, activityExpectedAnswer, linksJson)
  • quizzes (id PK, type, nullable day FK, title, daysJson)
  • quiz_questions (quizId/id composite PK, quizId FK, position, prompt, optionsJson, answerIndex, hint, explanation)

User-owned progress, attempt, and notification rows reference users with cascading deletes. assessment_attempts.assessmentId is not declared as a foreign key.

CHAPTER V

CONCLUSION

The Algorithm Hub project implements a local learning platform with algorithm explanations, interactive visualizations, direct browser-to-Wandbox code compilation, and an authenticated 30-day curriculum backed by SQLite. The backend validates activity results, grades daily and milestone quizzes, records progress, and revokes signed-out tokens.

The project has automated backend tests and a production frontend build. Browser/device acceptance, live Wandbox compilation, and public production deployment were not run in this review.
